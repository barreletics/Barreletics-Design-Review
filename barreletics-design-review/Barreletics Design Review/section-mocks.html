How to wash your performance skins.

Performance skins don’t need babying — but a few habits will roughly double their working life. Here’s the studio routine we recommend.

Most owners ruin their performance skins one of two ways: machine washing them on hot, or putting them away wet after a sweaty class. Both are fixable.

The 60-second rinse.

After class, run warm water through the underside of the shoe — not hot, not freezing. Add a small drop of mild soap. Massage briefly, rinse, and squeeze gently. Total time: under a minute.

Drying — the part people skip.

Air-dry, never the machine, and never direct sunlight for more than an hour. The grip surface is engineered for studio temperatures; UV slowly degrades it. Indoor drying keeps them gripping for years.

10 — Handoff

How we get this into production.

You asked the right question: hand off the spec, or build it in a draft theme? Do both — in a specific order. A draft theme is where the brand work actually lands. The spec doc is what keeps the developer (and you) from drifting back to the 14-template chaos a month from now.

Phase 1

Lock the tokens (1–2 days)

Before any visual work, the developer creates a duplicate of the live theme as a draft in Shopify admin and applies the locked token set there. Nothing in the customer-facing theme changes yet.

  • Duplicate live theme → name it Barreletics — 2026 system
  • Edit snippets/critical-css.liquid and snippets/css-variables.liquid to declare the 8 locked colors + 6-step type ramp as CSS variables
  • Edit config/settings_data.json: set type_header_font_family + type_base_font_family to Roboto, drop the unused cream/plum from header/footer settings
  • Add a top-level br-tokens.css asset that every section reads from

Output of phase: draft theme that looks ~95% identical to live, but with a single source of truth for color & type. No customer-facing change.

Phase 2

Normalize the 4 existing sections (3–5 days)

Keep the sections you already love. Strip them down so they read from tokens. No visual reskinning.

  • br-media-text-split → remove ~50 per-instance font/color/spacing settings from the schema
  • br-variants → remove ~57 per-instance settings · keep filter-tab logic intact
  • br-collab-hero (Coperni) → keep the field set, route colors/type through tokens
  • The “Why it works” HTML inside br-variants.custom_html → extract as sections/br-pillars.liquid

Output of phase: 4 existing sections that are token-driven · merchant editor stops being able to drift the brand on a per-section basis.

Phase 3

Add the 5 missing sections (5–7 days)

Build the five sections that don’t exist yet — each as a stand-alone sections/*.liquid file with its own minimal schema.

  • sections/br-hero.liquid · the full-bleed hero (Section 01)
  • sections/br-pillars.liquid · Why-it-works (Section 04)
  • sections/br-benefits.liquid · PDP benefit grid (Section 06)
  • sections/br-testimonial.liquid · single-quote section (Section 07)
  • sections/br-editorial.liquid · blog index + article (Section 09)

Output of phase: the full nine-section library lives in the draft theme. Existing live pages still work — old sections still exist.

Phase 4

Rebuild templates (3–4 days)

Recompose every template using only the nine sections.

  • Edit templates/index.json · home → 7 sections (per Page compositions above)
  • Edit templates/product.json · PDP → 6 sections
  • Edit templates/collection.json · collection → 5 sections
  • Edit templates/blog.json · blog → 2 sections
  • Edit templates/article.json · article → 3 sections
  • Delete: page.about, page.compare-open-vs-closed, page.free-people, page.test, page.blank-page, product.in-studio-template-v-3, product.brand-story, product.one-off-closed — and 6 more

Output of phase: 22 templates collapse to ~7. Every page composes from the same nine parts.

Phase 5

QA & cutover (2 days)

Walk the draft theme on staging. Compare against live, page by page, on desktop & mobile.

  • Spot-check every PDP — gallery, buy box, variant picker, sale flow
  • Test checkout end-to-end in the draft
  • Verify all redirects (the 14 deleted page templates) point somewhere sensible
  • Performance check: critical CSS budget, image lazy-loading, font weights
  • Publish draft → live. Snapshot the old theme as archive-pre-2026-system

Total estimate: 14–20 working days for one Shopify developer.
